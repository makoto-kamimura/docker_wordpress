# docs

仕様書の本体はリポジトリ直下の [README.md](../README.md)。`docs/` には、それ以外の資料を種類ごとのフォルダに分けて置く。

| フォルダ | 置くもの | 書く人 |
|---|---|---|
| [design/](design/) | 設計・計画の資料（README に載せきれない構成の詳細・テーマの開発履歴など） | 人 |
| [runbooks/](runbooks/) | 運用手順書（初回デプロイ・SSL・移行・停止なしの設定変更・トラブルシュートなど、作業ごと） | 人 |
| [incidents/](incidents/) | 障害のふりかえりと監査の記録（`YYYY-MM-DD-<概要>.md`） | 人 |
| [automation/](automation/) | 定期実行する自動化（n8n のワークフロー・エージェントのルーティン）の仕様と手順 | 人 |
| [tasks/](tasks/) | 不具合・要望・監査の対応タスク | 人 |

- **中身は git 管理外**（`.gitignore` の `/docs/**`）。本リポジトリは公開のため、ホスト名・SSH ポート・運用記録などを含む資料は追跡しない。git が追跡するのは、この `README.md` と各フォルダの `.gitkeep` だけである。
- `.gitkeep` はフォルダを git に残すためのもの。中身ができても消さなくてよい。
- 同じサーバーで動かしている追加アプリ（デモ）の資料は、このフォルダ構成には含めない（`docs/demo-apps*.md` と `platform/docs/` に置く）。
- 不具合・要望のタスクは `tasks/` にだけ置く。設計・運用の資料と混ぜない。
